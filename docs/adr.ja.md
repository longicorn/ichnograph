# アーキテクチャ決定記録

[English](adr.md)

## Goのバージョンとコードの配置

**状態:** 採用

IchnographはGoで実装します。最低Goバージョンは、Goプロジェクトがサポートする最も古いリリース系列に合わせます。2026年11月5日時点ではGo 1.26です。公式サポートの変更に合わせて最低バージョンを見直します。開発とビルドにはサポート対象のパッチリリースを使います。[Goのリリースポリシー](https://go.dev/doc/devel/release)を参照してください。

コマンドのエントリーポイントは`cmd/`に置き、実装は`internal/`配下で機能ごとのパッケージにまとめます。eBPF関連の機能は`internal/ebpf`から始めます。internalパッケージはモジュール内で再利用できますが、公開ライブラリのAPIではありません。責務が明確になった段階でパッケージを追加します。

## 実行時の根拠収集とCLIの責務境界

**状態:** 採用

Linuxでは[プロダクト要求](prd.ja.md)に従い、eBPFを使って実行時の根拠を収集します。収集処理は`internal/ebpf`に置いて`cmd/ichnograph`のエントリーポイントから分離し、必要に応じてプロセスの状態やファイルの識別情報などを使ってGo側で観測結果を補足します。ネイティブ連携に必要な場合はcgoを使用でき、そのビルドへの影響を文書化します。

`cmd/ichnograph`のCLIはサブコマンド体系を採用し、特権を要する実行時トレース収集（`ichnograph trace`）を、非特権で動作する正規化や外部メタデータ統合の後続サブコマンドから明確に分離します。`ichnograph trace`は`internal/ebpf`を呼び出し、構造化された収集結果をJSON形式で出力するとともに、既定の`/var/log`および`.log`の収集後除外フィルタ（`-include-logs`で解除可能）などのコマンドレベルの出力オプションを適用します。

`trace`サブコマンドに関する設計判断は[traceアーキテクチャ決定記録](trace/adr.ja.md)で定義し、プローブの選定、プロセス追跡、イベントの抑制と重複排除、パス解決、損失時の扱いに関するeBPFコレクタの設計判断は[eBPFアーキテクチャ決定記録](ebpf/adr.ja.md)で定義します。

## 実行時ログの正規化と外部情報マッピングの分離

**状態:** 採用

`internal/ebpf`は特権を要するカーネルイベントの収集と生レコードの出力に専念させ、収集後の整理および外部情報との統合は非特権で動作する別段階として分離します。

1. **リポジトリ単体で完結する実行時ログの正規化:** コレクタが出力した生レコードをGo側で集約し、観測されたファイル（パス、ハッシュ、アクセス種別）、プロセスツリー、通信先エンドポイント、IPC活動、および収集上の制限事項からなる正規化ビューを生成します。この段階は特定の言語やパッケージ管理ツールに依存させず、テストスキップ判定などの用途を`ichnograph`単体で完結できるようにします。
2. **共通スキーマによる外部情報の結合:** 各言語のパッケージマネージャやSBOM形式、OSパッケージ管理、ミドルウェア固有の解析ロジックをすべて本体に組み込むのではなく、共通のマッピングスキーマと結合ルールを定義します。外部ツールやアダプタが、コンポーネントの所有関係（ファイルパス、バイナリ内のシンボル、通信先エンドポイントとコンポーネント・バージョンの対応）と宣言上の静的依存関係（`Gemfile.lock`やSBOMなどから得られる関係）を共通形式で提供し、正規化ログと突き合わせる構成とします。
3. **帰属状態の明示と制限事項の引き継ぎ:** 正規化ログと外部マッピングを結合する際は、各コンポーネントや関係が「実行時に観測されたものか」「静的定義にのみ存在するものか」「実行時に観測されたがどのコンポーネントにも紐付かない未帰属のものか」を区別して保持します。あわせて、コレクタが記録したイベント損失や制限事項を統合結果にも引き継ぎ、利用側で根拠の信頼度を判断できるようにします。
