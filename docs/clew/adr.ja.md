# アーキテクチャ決定記録: clewサブコマンド

[English](adr.md)

## 非特権サブコマンドの配置とオプション駆動パイプライン

**状態:** 採用

後処理機能は、`trace` にオプションを追加したり変換ステップごとに別々のサブコマンドを増やしたりするのではなく、`cmd/ichnograph`（`clew.go`）内の非特権サブコマンド `ichnograph clew` として配置します。特権を要するカーネル収集を `trace` に分離したまま、`clew` のオプション（まずは `-group-by pid,tid`）として処理を指定する設計にすることで、今後のエンリッチメントや外部メタデータ統合を段階的に追加できる単一の合成可能なパイプライン入口を確立します。初期のグルーピング処理は自己完結しているため CLI ディスパッチと同じ `cmd/ichnograph` に直接配置しており、将来のパイプライン拡張で必要になった場合に `internal/` パッケージへ切り出せる構成としています。

## フォーマット判別に基づく入力契約（`ichnograph.clew.v1`）

**状態:** 採用

`clew` は `ichnograph trace` の出力形式を変更することなく、入力 JSON オブジェクトのトップレベル `format` フィールドの有無・値によって生のトレースログと処理済みパイプライン出力を判別します。

- `format` が存在しない場合、トップレベルに `records` 配列を持つ生の `trace` JSON として扱い、`pid` と `tid` でグルーピングしたうえで `records` を削除し、`format` に `"ichnograph.clew.v1"` を設定します。
- `format` が `"ichnograph.clew.v1"` の場合、`processes` -> `threads` -> `records` の階層構造と、各レコードの `pid` および `tid` が親グループと一致することを検証したうえで再出力します。それ以外の `format` 値はエラーとして拒否します。

## 2階層配列スキーマと生 JSON フィールドの保持

**状態:** 採用

`pid,tid` でグルーピングする際、`clew` は ID をキーとするマップではなく 2 階層の配列（`pid` 昇順の `processes` -> `tid` 昇順の `threads` -> 観測順を維持した `records`）を出力します。配列構造とすることで出力順序の決定性を保証し、将来のステージでプロセス単位やスレッド単位のメタデータを自然に付与できるようにしています。

また、未知のフィールドや将来追加されるフィールドを失わずにパイプラインを合成できるよう、`clew` はトップレベル JSON オブジェクトおよび各レコードを `json.RawMessage` として扱います。これにより、生の `trace` 入力をグルーピングする際にはトップレベルの完全性メタデータ（`lost`、`loss_breakdown`、`descendants_remaining`、`limitations`）やレコード単位の拡張フィールドがそのまま保持され、すでにグルーピング済みの `"ichnograph.clew.v1"` 入力を再処理する際にはグループ単位の拡張フィールドや既存の順序も維持されます。

## ストリーム指向の入出力とフェイルクローズ出力

**状態:** 採用

`ichnograph clew` は入力と `-o` 出力の既定値をいずれも `-`（`/dev/stdin` からの読み込みおよび `stdout` へのインデント付き・末尾改行付き JSON 出力）とし、シェルパイプとファイルの双方でパイプラインを連結できるようにします。入力のパース、スキーマ検証、グルーピングはすべてメモリ上で完了してから出力先へ書き込むため、CLI フラグ不正（終了コード `2`）や入力・書き込みエラー（終了コード `1`）の際には、標準エラーにエラーを出力し `-o` へ不完全な出力を書き込まずに終了します。
