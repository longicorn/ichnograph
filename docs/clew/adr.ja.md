# アーキテクチャ決定記録: clewサブコマンド

[English](adr.md)

## 非特権サブコマンドの配置とオプション駆動パイプライン

**状態:** 採用

後処理機能は、`trace` にオプションを追加したり変換ステップごとに別々のサブコマンドを増やしたりするのではなく、`cmd/ichnograph`（`clew.go`）内の非特権サブコマンド `ichnograph clew` として配置します。特権を要するカーネル収集を `trace` に分離したまま、`clew` のオプション（まずは `-group-by pid,tid`）として処理を指定する設計にすることで、今後のエンリッチメントや外部メタデータ統合を段階的に追加できる単一の合成可能なパイプライン入口を確立します。CLIのディスパッチは `cmd/ichnograph` に置き、パイプラインの実装は `internal/clew` に置きます。

## フォーマット判別に基づく入力契約（`ichnograph.clew.v1`）

**状態:** 採用

`clew` は `ichnograph trace` の出力形式を変更することなく、入力 JSON オブジェクトのトップレベル `format` フィールドの有無・値によって生のトレースログと処理済みパイプライン出力を判別します。

- `format` が存在しない場合、トップレベルに `records` 配列を持つ生の `trace` JSON として扱い、`pid` と `tid` でグルーピングしたうえで `records` を削除し、`format` に `"ichnograph.clew.v1"` を設定します。
- `format` が `"ichnograph.clew.v1"` の場合、`processes` -> `threads` -> `records` の階層構造と、各レコードの `pid` および `tid` が親グループと一致することを検証したうえで再出力します。それ以外の `format` 値はエラーとして拒否します。

## 2階層配列スキーマと生 JSON フィールドの保持

**状態:** 採用

`pid,tid` でグルーピングする際、`clew` は ID をキーとするマップではなく 2 階層の配列（`pid` 昇順の `processes` -> `tid` 昇順の `threads` -> タイムスタンプ順の `records`）を出力します。配列構造とすることで出力順序の決定性を保証し、将来のステージでプロセス単位やスレッド単位のメタデータを自然に付与できるようにしています。

また、未知のフィールドや将来追加されるフィールドを失わずにパイプラインを合成できるよう、`clew` はトップレベル JSON オブジェクトおよび各レコードを `json.RawMessage` として扱います。これにより、生の `trace` 入力をグルーピングする際にはトップレベルの完全性メタデータ（`lost`、`loss_breakdown`、`descendants_remaining`、`limitations`）やレコード単位の拡張フィールドがそのまま保持され、すでにグルーピング済みの `"ichnograph.clew.v1"` 入力を再処理する際にはグループ単位の拡張フィールドとグループの順序も維持されます。

## ストリーム指向の入出力とフェイルクローズ出力

**状態:** 採用

`ichnograph clew` は入力と `-o` 出力の既定値をいずれも `-`（`/dev/stdin` からの読み込みおよび `stdout` へのインデント付き・末尾改行付き JSON 出力）とし、シェルパイプとファイルの双方でパイプラインを連結できるようにします。入力のパース、スキーマ検証、グルーピングはすべてメモリ上で完了してから出力先へ書き込むため、CLIフラグ不正（終了コード `2`）や入力エラー（終了コード `1`）の場合は、標準エラーにエラーを出力し、`-o` には書き込みません。書き込みエラーも終了コード `1` で報告しますが、出力が途中まで書き込まれる場合があります。

## パイプラインパッケージの切り出し（`internal/clew`）

**状態:** 採用

`clew` が初期のグルーピングを超えて述語のパース・評価、レコードのフィルタリング、条件付きタグ付け、ファイル内容検査を含むように拡張されたことに伴い、パイプラインの中核ロジックを `cmd/ichnograph` から `internal/clew` へ切り出します。`cmd/ichnograph/clew.go` は CLI フラグ解析、ヘルプ・Usage 表示、終了コード制御、stdin/stdout/ファイル入出力のディスパッチのみを担当し、`internal/clew` が合成可能なパイプラインステージとドメイン型を保持します。これにより `cmd/ichnograph` を CLI 配線に集中させつつ、パイプライン各ステージを独立して単体テストできるようにします。

## 単一実行内のステージ順序とフィルタ評価ルール

**状態:** 採用

1 回の `ichnograph clew` 呼び出しで複数の変換オプションが指定された場合、各ステージは以下の固定順序で実行します。

1. **入力のデコードと検証**: 生の `trace` JSON を読み込むか、`ichnograph.clew.v1` 入力を検証し、共通の内部表現へ展開します。
2. **フィルタリング（`-include` / `-exclude`）と空グループの削除**: 各レコードに対して `-include` および `-exclude` 述語を評価します。`-include` が 1 つ以上指定された場合はいずれかの `-include` に一致するレコードを対象とし（`OR`）、いずれかの `-exclude` に一致するレコードを除外します（`OR(include) AND NOT OR(exclude)`）。フィルタリング後、`records` が空になった `thread` は `threads` から削除し、`threads` が空になった `process` は `processes` から削除します。
3. **タグ付け（`-tag` / `-tag-file-type`）**: フィルタを通過したレコードに対して、ユーザー定義の条件付きタグ（`-tag`）およびファイル内容に基づく種別タグ（`-tag-file-type`）を付与します。タグ付けより先にフィルタリングを行うことで、除外対象レコードに対する不要なファイルシステム I/O やタグ評価を回避します。
4. **グルーピングと出力**: 生の `trace` レコードを `pid,tid` でグルーピング（または検証済みの `ichnograph.clew.v1` グループ構造を保持）し、インデント付き JSON として出力します。

## 統一フィールド／値述語モデル

**状態:** 採用

`-include`、`-exclude`、`-tag` は、各レコードのトップレベルフィールドに対して動作する単一の述語パーサーおよび評価器を共有します。

- **構文**: 完全一致には `<field>=<value>`、部分文字列一致やパターン一致（パス部分文字列やサフィックスなど）には `<field>~=<value>` を使用します。条件付きタグ付けルールは `<tag>:<predicate>`（例: `ruby:path~=.rb`）の形式とし、CLI 引数パース時にタグ名と述語構文の双方を検証します（構文不正時は終了コード `2` で終了）。
- **評価**: デコードされたレコードのトップレベル JSON オブジェクトからフィールド値を参照します。完全一致（`=`）は JSON の文字列・数値・真偽値と比較し、部分文字列／パターン一致（`~=`）は文字列値に対して適用します。対象フィールドが欠如している場合や型が一致しない場合は、エラーとせず非一致として評価します。

## 生 JSON 保持と両立するレコード `tags` のマージ方式

**状態:** 採用

`trace` スキーマ全体を再モデル化せずに未知のフィールドや将来追加されるフィールドをパイプライン間で保持するため、`clew` は引き続き各レコードを `json.RawMessage` として保持します。新しいタグが付与されないレコードは変更せずそのまま出力します。1 つ以上のタグを付与するレコードについては、そのレコードのトップレベル JSON オブジェクトマップのみを一時的に展開し、既存の `tags` 文字列配列があれば読み出して順序を保ったまま重複を排除して新しいタグを追記し、他のキーを失わずに再シリアライズします。

## `-tag-file-type` における純 Go ヘッダ検査とキャッシュ

**状態:** 採用

`-tag-file-type` によるファイル内容ベースの種別検出は、将来の外部ツール連携（`file` コマンド等）をパイプライン制御の変更なしに追加できるよう、検出インターフェースの背後に純 Go 実装として構築します。

- **パス解決と先頭固定長読み込み**: 各レコードについて、空でない `resolved_path` があればそれを優先し、なければ `path` を参照します。通常ファイルのみを対象として先頭の固定バイト長（ヘッダバイト）のみを読み取り、マジックバイト（`elf` を示す `\x7fELF` 等）および shebang 行（`#!` による `ruby`、`python`、`sh`、`bash` 等のインタープリタ名）を検査し、組み込みのパス／拡張子プリセットと組み合わせてタグを決定します。
- **実行単位のキャッシュと安全なスキップ**: 同一パスへの重複したファイルシステム I/O を避けるため、1 回の `clew` 実行内では解決済みファイルパス単位で検出結果をメモリ上にキャッシュします。後処理時点でファイルが存在しない、通常ファイルでない、または読み取れない場合は、パイプラインを失敗させずそのレコードへの内容ベースタグ付けを静かにスキップします。

各スレッドのレコードはRFC 3339形式のタイムスタンプの昇順に安定ソートします。同時刻のレコードは入力順を保持し、タイムスタンプがないレコードや不正なレコードは有効なタイムスタンプを持つレコードの後に入力順で配置します。生の入力とグループ化済み入力の両方に適用します。
