# プロダクト要求: traceサブコマンド

[English](prd.md)

## 目的

`ichnograph trace`サブコマンドは、対象コマンドを実行し、ファイルアクセス、プログラム実行、ディスクリプタ利用、パイプやFIFOの活動、およびネットワーク接続試行の実行時観測結果を構造化されたJSONファイルとして出力します。[ichnograph全体のプロダクト要求](../prd.ja.md)における生ログ収集のエントリーポイントを担い、Linux環境では[eBPFコレクタ](../ebpf/prd.ja.md)を用いてカーネルレベルの観測情報を収集します。

## コマンドラインインターフェース

```sh
ichnograph trace [-include-logs] -o output.json command [args...]
```

- **`-o <path>`（必須）**: 収集したレコードと完全性メタデータ（`lost`、`loss_breakdown`、`descendants_remaining`、`limitations`）を書き出すJSONファイルのパスを指定します。
- **`-include-logs`（任意）**: `path`または`resolved_path`が`/var/log`配下にあるレコードや`.log`で終わるレコードを除外せず保持します。
- **`command [args...]`（必須）**: トレース対象として実行するコマンドとその引数を指定します。
- `-o`が指定されていない場合、または実行対象コマンドが指定されていない場合は、標準エラー出力に使用方法を表示して終了コード`2`で終了します。

## 収集後のログ除外フィルタリング

- 既定（`-include-logs`未指定時）では、収集完了後に正規化（`filepath.Clean`）した`path`または`resolved_path`が`/var/log`と一致するもの、`/var/log/`で始まるもの、または`.log`で終わるレコードを出力から除外します。
- 既定のフィルタを適用した場合は、`/var/log`配下および`.log`で終わるレコードが既定で除外されていること、相対パスやディスクリプタパスは未解決または不正確な場合があること、`-include-logs`で含められること、およびフィルタリングは収集後に行われカーネル側のイベント量や損失を減らすものではないことを`limitations`に記録します。

## プロセス実行と終了ステータス

- Linux環境における対象プロセスの実行と実行時トレースの収集は[eBPFコレクタ](../ebpf/prd.ja.md)に委譲します。
- 収集および出力ファイルの書き込みが成功した場合は、対象コマンドの終了ステータスで終了します。
  - 対象コマンドの通常の終了コード（`0`〜`255`）
  - シグナルにより終了した場合は`128 + signal`
  - 対象コマンドが見つからない場合は`127`
  - 対象コマンドが存在するが実行できない場合は`126`
- 収集処理の失敗や出力JSONファイルのシリアライズ・書き込みに失敗した場合は、標準エラー出力にエラーを表示して終了コード`1`で終了します。
