# アーキテクチャ決定記録: traceサブコマンド

[English](adr.md)

## サブコマンドによるディスパッチと内部ヘルパーハンドシェイク

**状態:** 採用

実行時トレースの収集は、ルートCLIに直接対象コマンドを渡すのではなく、`cmd/ichnograph`内の`ichnograph trace`サブコマンド配下に配置します。`trace`は任意の位置引数（`command [args...]`）を受け取り、かつeBPFプログラムのロードに特権を必要とするため、専用のサブコマンドに分離することで位置引数の解釈の曖昧さを防ぎ、非特権で動作する後続サブコマンド（実行時ログの正規化や外部メタデータ統合など。[ルートアーキテクチャ決定記録](../adr.ja.md)を参照）と特権収集処理の境界を明確に保ちます。

サブコマンドやフラグを解析する前に、`cmd/ichnograph`は起動直後に内部引数`--ichnograph-exec-helper`を判定してヘルパー処理へ分岐します。これにより、`internal/ebpf`をCLIのサブコマンド構造に依存させることなく、`internal/ebpf.Run`が必要とする初期プロセス追跡用のハンドシェイク（[eBPFアーキテクチャ決定記録](../ebpf/adr.ja.md)を参照）を維持します。

## コレクタへの委譲と収集後フィルタリング

**状態:** 採用

`ichnograph trace`は専用のフラグセット（`-o`および`-include-logs`）を解析し、残りの位置引数を渡して`internal/ebpf.Run`を呼び出します。カーネルプローブの管理、イベントの対応付け、パス解決、ファイルハッシュ計算は`internal/ebpf`内部に閉じ込め、CLIレベルの関心事は`cmd/ichnograph`側で処理します。

- `-include-logs`が指定されていない限り、`internal/ebpf.Run`から結果が返った後にユーザー空間で`/var/log`配下および`.log`で終わるレコードの除外フィルタを適用し、対応する制限事項（`limitations`）を結果に追記します。
- 得られた`ebpf.Result`をインデント付きJSON（末尾改行付き）にシリアライズして`-o`のパスへ書き出し、`internal/ebpf.Run`から返された終了コードでプロセスを終了します。
