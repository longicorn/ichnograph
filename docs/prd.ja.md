# プロダクト要求: ichnograph

## 目的

Ichnographは、プロダクトのある機能が何に依存し、何から影響を受けるかを、実行環境に即して調べるための基盤です。コマンドの実行中にアクセスしたファイルを記録するichnoの考え方を発展させます。調査結果は、コンポーネントの更新時の影響調査に役立て、Nagiのリバース対応を支える技術としての利用も想定します。

## プロダクトの方向性

利用者は機能を実行し、得られた根拠を使って依存関係を調べます。将来的には、JavaScript/TSXやRubyを含むアプリケーションコードと、ライブラリやネイティブ拡張、データベース、サードパーティサービス、OSのライブラリやコマンド、カーネルの機能との関係を調べられるようにします。実行時の観測結果をSBOMやパッケージ情報と結び付け、依存関係をグラフで表現します。

実装にはGoを使います。eBPFでPID/TID、イベント種別、タイムスタンプ、ファイルやソケットの識別情報、必要に応じてスタックIDを収集する構想です。Go側ではELF、DWARF、Goシンボル、パッケージ情報などを使って観測結果に周辺情報を付加します。CやGoのようなコンパイル言語の解析にはDWARFの利用を検討します。これらは今後の方向性であり、初期段階での対応範囲を保証するものではありません。

## 最初のマイルストーン

Linuxで対象コマンドを実行し、eBPFでichnoの出力に相当するファイルアクセス情報を取得できることを実証します。

- 観測したファイルアクセスについて、解決できる場合はパスを記録し、PID、TID、タイムスタンプ、イベント種別、取得可能な場合はファイルのハッシュを記録します。
- コマンドと関連する子プロセス、スレッドを追跡し、後続の処理に使えるJSON形式で出力します。
- 取得できなかった情報や、把握できたイベント損失、収集エラーを明示し、不完全な結果を完全なものと誤認しないようにします。
- アクセス先が既知のコマンドと子プロセスを使って結果を検証し、取得した項目をichnoの出力と比較します。

使用するプローブ、ハッシュの計算時点とアルゴリズム、必要な権限、対応カーネルバージョンは実装時に決定します。ハッシュは計算時点の内容を表すため、ファイルが変更された場合、アクセス時の内容と一致するとは限りません。

## 今後の機能

必要に応じてプロセスやネットワークの活動、スタック情報にも収集対象を広げます。実行ファイルやデバッグ情報、言語とOSのパッケージ、対象環境のSBOMを使って観測結果を対応付けます。機能から依存先を辿り、逆方向に影響の可能性を調べられるグラフを構築します。コンテナ対応と言語固有の詳細な対応付けは今後の検討事項であり、最初のマイルストーンの必須条件には含めません。

## 結果の解釈と限界

観測した関係と周辺情報から推定した関係を区別し、それぞれの根拠と限界を保持します。1回の実行で分かるのは、その実行中に捕捉した活動だけです。結果に現れないことは、依存関係が存在しない証拠にはなりません。動的言語、デバッグ情報の欠如、イベント損失、非同期処理や分散実行、外部サービスなどによって、対応付けが制限される場合があります。部分的な観測結果を完全な依存関係の一覧として提示しません。
