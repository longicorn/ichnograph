# プロダクト要求: ichnograph

[English](prd.md)

## 目的

Ichnographは、プログラムや機能を実行した際に、実際にどのような構成要素が使われ、何に依存しているかの全体像を実行環境に即して把握するための基盤です。コマンドの実行中にアクセスしたファイルやプロセス、通信などの実行時情報を記録し、次のような用途に役立てます。

- テスト実行時に観測した依存情報をもとに、次回実行時に条件や依存先が変わっていなければテストケースの実行をスキップするといったテストの最適化。
- フレームワークやライブラリ、OSコンポーネントのアップデート時に必要となる依存関係や影響範囲の調査負担の軽減。

## プロダクトの方向性

利用者は対象のプログラムや機能を実行し、得られた根拠からその構成と依存関係の全体像を調べます。特定の言語に限定せず、実行時の観測結果をパッケージ情報やビルド成果物、SBOMと結び付けて依存関係をグラフで表現します。

把握したい構成要素は、プログラムの層を跨いで広がります。たとえば、利用しているパッケージのコードだけでなく、ネイティブ拡張が含まれる場合はそのビルド済みバイナリやリンク先の動的ライブラリ、ソケット通信を行っている場合はTCP等の通信先にあるデータベースや外部サービスの種類・バージョン、さらにOSのコマンドやライブラリ、カーネル機能までのつながりを対象とします。

対象とするプログラムは大きく次の2種類を想定します。

- **軽量言語（LL）・インタープリター系:** 実行時に読み込まれるスクリプトやパッケージのコード、ネイティブ拡張、およびそれらが読み込む動的ライブラリなどのアクセス証跡から利用構成を辿ります。
- **コンパイル言語系:** ファイルアクセスだけではバイナリ内部でどのパッケージや関数が使われたか判別できないため、DWARFなどのデバッグ情報やシンボル、コールグラフやスタック情報を組み合わせて、実際に利用されている構成要素を特定します。

## 観測の粒度

使用されたファイルやコード、ライブラリ、および依存関係に関わるディスクリプタやソケットの使用を特定できるだけの根拠を記録します。読み書きのたびの記録よりも、プログラムの構成や依存関係の把握に意味のある使用や関係を捉えることを重視します。ディスクリプタの内容や通信ペイロードの収集は目的に含めません。外部通信については、可能な範囲で通信先、プロトコル、背後のミドルウェアや関連ライブラリを特定します。対応付けには追加の根拠が必要な場合があります。

実際のワークロードで動作し、イベント損失を抑えられる収集を目指します。得られた根拠を評価できるよう、把握できた損失、エラー、取得できない情報を示します。継承されたディスクリプタなどを通じたアクセスの根拠も保持できる粒度とし、固定のシステムコール一覧で要件を定めません。

## 最初のマイルストーン

Linuxで対象コマンドを実行し、eBPFでファイルアクセス情報と、プロセス、パイプやFIFO、ネットワーク接続の基本的な根拠を取得できることを実証します。

- 観測したファイル、プロセス、ディスクリプタ、ネットワークの活動について、解決できる場合はパスを記録し、PID、TID、タイムスタンプ、イベント種別、取得可能な場合はファイルのハッシュを記録します。
- コマンドと関連する子プロセス、スレッドを追跡し、後続の処理に使えるJSON形式で出力します。
- 実際のワークロードに対応できるようイベント量を適切に抑え、取得できなかった情報や把握できたイベント損失、収集エラーを明示します。
- アクセス先が既知のコマンドと子プロセスを使って結果を検証します。

LinuxのeBPFコレクタにおける収集対象、補完処理、重複排除、損失報告の詳細な要件は[eBPFプロダクト要求](ebpf/prd.ja.md)で定義します。

## 実行時ログの正規化と外部情報との統合

あらゆる言語やパッケージ管理形式の解析処理をコレクタ本体に抱え込むのではなく、収集後の情報を次の2段階で整理・統合します。

1. **実行時観測ログの正規化と集約:** `ichnograph`単体で生のイベント列を整理し、実際に使用されたファイル（正規化パス、ハッシュ、実行・メモリマップ・読み取り・書き込みといった役割）、プロセスの親子関係、通信先エンドポイント、パイプやFIFOの利用、および完全性メタデータ（`lost`と`limitations`）に集約します。テストスキップの判定など、実行時のアクセス集合とハッシュで足りる用途はこの正規化ログ単体で完結できます。
2. **外部情報との結合ルールと統合フォーマット:** 正規化された実行時ログと、言語・環境固有の外部情報（`Gemfile.lock`とパッケージ配置パス、OSパッケージのファイル一覧、SBOM、DWARF等のシンボル解析結果、データベース等の接続先定義など）を合わせるための共通ルールと表現フォーマットを定義します。
   - 外部情報は、**所有関係**（どのコンポーネントやサービスがどのファイルパス・バイナリ領域・通信先エンドポイントに対応するか）と、**静的な依存関係**（コンポーネント間の宣言上の依存）の2つとして共通化します。
   - 統合結果のフォーマットでは、**実行時に観測された構成要素・関係**、**静的定義には存在するが今回の実行では観測されなかった構成要素**、および**どの既知コンポーネントにも紐付かなかった未帰属のアクセス**を区別して表現します。

対象プログラムの構成をより深く把握するため、スタックやコールグラフの情報、DWARFなどのデバッグ情報解析、ソケット通信先のサービス特定との連携を段階的に広げます。

## 結果の解釈と限界

観測した関係と周辺情報から推定した関係を区別し、それぞれの根拠と限界を保持します。1回の実行で分かるのは、その実行中に捕捉した活動だけです。結果に現れないことは、依存関係が存在しない証拠にはなりません。動的な読み込み、デバッグ情報の欠如、イベント損失、非同期処理や分散実行、外部サービスなどによって、対応付けが制限される場合があります。部分的な観測結果を完全な依存関係の一覧として提示しません。
